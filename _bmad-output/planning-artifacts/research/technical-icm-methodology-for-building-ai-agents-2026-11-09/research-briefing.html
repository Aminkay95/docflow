Executive summary

ICM is Interpretable Context Methodology — a 2026-vintage, filesystem-first approach where numbered folders are workflow stages and markdown files are prompts/context, instead of framework orchestration code [1] [2] [3]. Name verified by three independent publishers; earlier spellings (Interpreted, MWP) are Feb–Mar 2026 renames [4] [6]. No primary supports “Intelligent Context Methodology” [27]. ICM is orthogonal to dominant patterns: prompt chaining instantiated as folders, MCP (Model Context Protocol) as complementary layer [2].

Maturity is thin and forked: RinDig 21 commits Feb–Jul 2026, 1.4k stars [1] [6]; NathanForster fork “not yet deployed at organizational scale; pilot in progress” [3]; adoption NDA-limited and control-free [2]; larger training numbers single-aggregator [7]. Runtime frameworks LangGraph / OpenAI Agents SDK / CrewAI are dated-active in access week [21] [22] [23]; AutoGen release-stalled since 2025-09-30 [24].

Biggest caveat: three structural dialects coexist (RinDig 5 layers [1], gist 3-layer [4], Nathan 3-file [3]) with no controlled token comparison [2]. ReAct 34/10 [13] and multi-agent 90.2% / 80% / 15× [12] are unverified single-publisher — do not rest adoption on them.

2. Architecture patterns in practice

Three dialects: RinDig L0 CLAUDE.md (~800) / L1 CONTEXT.md (~300) / L2 Stage (~200–500) / L3 Reference / L4 Working [1]; gist 3-layer routing with What-to-Load / What-NOT-to-Load [4]; Nathan ICM.md / CONTEXT.md / AGENT.md + staged runner [3]. Stage contract Inputs/Process/Outputs + checkpoints + audits [2]. Principles: “One stage, one job; Plain text as interface; Layered loading; Every output is an edit surface; Configure the factory, not the product” [2]. Claimed 2K–8K per stage vs 30K–50K monolithic, “No controlled comparison” [2]. verified claim unverified savings

Mapping: “prompt chaining at the filesystem level” — not ReAct [2] verified. Orchestrator-workers with filesystem contracts (Opus delegates to Sonnet via Agent Teams) [2]; gist worktree sub-agents [4]. Five Anthropic workflows: chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer [11] verified pattern (stale for landscape). ReAct [13], Reflexion 91% HumanEval [14], Plan-and-Solve [15], ToolNode loop (deprecated API) [16].

Steps: Dec 2024 “start simple” [11] superseded by Managed Agents session/harness/sandbox [17] verified successor. Resolution: simple for predictable workflows; framework patterns for long-horizon / parallel-breadth / high-value (not shared-context coding, not low-value 15×) [12]. Production sequence: Console simulation → delegate teaching → effort scaling → heuristics → wide-then-narrow → extended thinking → parallel tool calls [12]. Numbers 34/10 [13] and 90.2%/80%/15× [12]: unverified single-publisher.

Cross-dimension insights

  • ICM = context architecture, not reasoning — overlaps ACI simplicity [11][2], substitutes filesystem for code-delegated subagents [12]; fits sequential file-shaped pipelines [1], inverts for shared-context coding [12].
  • Token budgets collide with re-send costs: 2K–8K/stage [2] vs 2.17M re-sends + 5-min TTL [18] — needs cache-stable prefixes.
  • Freshness splits decision: ICM primaries Mar–Aug 2026 inside AI window; Dec 2024 patterns usable ≤2 yr [11], landscape only via Apr 2026 successor [17].

Recommendations

  1. Context layer, not framework. Use [1][2] for sequential file pipelines; keep ReAct/orchestrator-workers as reasoning [12][13]. verified high
  2. Pin one dialect. 5-layer vs 3-layer vs 3-file coexist [1][4][3] verified high.
  3. Do not budget on unverified numbers [13][12][2][7] verified withholding.
  4. Dated framework choice: LangGraph [21] / CrewAI [22] over OpenAI alpha [23]; pause AutoGen [24] high / medium.
  5. Cache-first ICM workspaces [18] medium single-vendor.
  6. Gate on independent eval: ~20 queries + rubric + human test [12]; all-traces checks [19][20] medium.
