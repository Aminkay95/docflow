- (direction) Source: forged-idea.md from bmad-forge-idea session 2026-10-30, which supersedes the original file-centric intake pipeline concept
- (decision) v1 is the caller-grouped extraction API. Grouper, email ingestion, ERP posting, on-prem stack all deferred to v2
- (capability) CAP-1 Caller submits a grouped document set under an optional job_ref and receives per-document structured JSON in one asynchronous operation
- (capability) CAP-2 Page-level segmentation of every submitted file, including files containing several document types
- (capability) CAP-3 Typed per-document extraction across all seven document types, with page and bounding-box provenance on every field
- (capability) CAP-4 Deterministic validation producing a post-or-review decision with human-readable reasons per failed check
- (capability) CAP-5 Cross-document conflict detection within the asserted group, reported per field with the disagreeing source documents
- (capability) CAP-6 Two-track review queue (extraction review vs conflict review) with correction capture that feeds the labelled dataset
- (capability) CAP-7 Trust-ramp records per client, supplier, document type and template fingerprint, scaffolded at 100 percent review in v1
- (capability) CAP-8 Repeat calls under the same job_ref accumulate and reconcile against previously stored results for that job_ref
- (capability) CAP-9 Seven document type schemas defined, based on standard spines, with local extensions isolated in a per-type block
- (constraint) Emitted values are always as-stated on the source page. Arithmetic runs only as validation and is never emitted as data
- (constraint) No duty or CIF computation. Emit incoterm plus goods value, freight and insurance as separate stated fields so no derived value is fabricated
- (constraint) Model confidence and logprobs may order the review queue but may never decide the post-or-review gate
- (constraint) Every emitted field carries page and bounding-box provenance; a field without provenance is not emitted
- (constraint) Grouping is caller input. The platform validates the asserted group and reports conflicts but never regroups or infers membership
- (constraint) Cloud-first. A provider adapter sits behind every model call so the inference stack is swappable
- (constraint) Schemas adopt standard spines: UBL 2.1 / Peppol BIS Billing 3.0 for the invoice family, WCO Data Model for custom entry, proprietary extension blocks for delivery order, port pass and verification memo
- (constraint) National context is a field value, never baked into field names, so the model is not Kenya-locked
- (constraint) Asynchronous submission contract: accept group, return result id, deliver via webhook with polling fallback
- (constraint) Deterministic idempotency key per document (content hash plus job reference) on every stored record
- (constraint) Multi-shipment containers are refused loudly with a count and a split instruction, never silently partially processed
- (constraint) Email may alert; resolution happens only inside the authenticated platform, never by email reply
- (constraint) Data model: file is a container, page is the atom, segment is the unit of extraction
- (constraint) Market is Kenya: KRA iCMS for declarations, KenTrade TradeNet for the single window and IDF, KPA/KWATOS for port-side documents
- (constraint) Non-goal: no email or mailbox ingestion, no grouper, no job assembly beyond the caller-supplied job_ref
- (constraint) Non-goal: no ERP posting in v1; clients consume the response and webhook
- (constraint) Non-goal: no on-premise deployment or local inference stack
- (constraint) Non-goal: no automated trust-ramp promotion; v1 runs entirely at 100 percent review
- (constraint) Non-goal: not a general document AI; scope is the seven Kenyan trade document types
- (assumption) Every document in a submitted group relates to one bill of lading, asserted by the caller rather than verified by the platform
- (assumption) Real Kenyan trade documents are obtainable from a working clearing agent for the labelled eval set
- (assumption) A large fraction of intake arrives as digital PDFs with an embedded text layer, enabling the cheap reader path
- (assumption) v1 buyers are technical and can call an API; SMB clearing firms without a TMS are out of reach until v2

- (decision) Documents are stored in three tiers: staging during processing (hours), review window for page images (until decision plus bounded grace), archive off by default and opt-in per tenant. Expiry enforced by a scheduled job with a test; backup windows count against any deletion promise
- (constraint) Provenance is portable: every field carries page index, bounding box and document hash so a client overlays against their own copy. This is what makes the no-archive default defensible
- (event) SPEC constraints updated with retention tiers and portable provenance; stack.md given a Retention section
- (lock) Documents purged six hours after the job reaches a terminal state. Re-extraction is a development concern only; in production, needing to re-extract means the job was not finished. Archive tier removed
- (assumption) Terminal state means posted or review-resolved. A job with an open review item or unresolved conflict is not terminal and its purge clock has not started
- (constraint) Purge does not purge the data: the immutable extraction record (values, provenance, hash) outlives the file and needs its own separate retention policy. S3 non-current versions must be expired on the same schedule or the purge is a fiction. Purge failures must be observable via a metric and alert
- (event) Six-hour post-terminal purge replaces the three-tier retention model in SPEC and stack.md
- (lock) Extraction record retained for the life of the account plus ninety days after termination, then deleted. Exportable in full on request and deleted on request before expiry. Exportability is what makes the retention defensible
- (constraint) Telemetry never retains document content: logs, traces, error reports and metrics carry hashes, model versions, timings, token counts and field outcomes only, never page images, document text or prompt payloads. Provider-side tracing is a deliberate time-boxed exception with its own deletion date
- (note) Industry pattern confirmed as files-short, output-long. Kenyan tax and customs record-keeping duty of roughly five years sits on the importer, not on the processor, so aggressive document purge is aligned with data minimisation under the Kenya Data Protection Act.
